# PQTerm - Claude Code Build Guide

Implementation companion to `PQTerm_MVP_Document.md` (the MVP spec). That doc is the *what and why*; this file is the *how*. Drop both in the repo root. Suitable as seed content for `CLAUDE.md`.

**Project:** pure post-quantum E2EE 1:1 messenger, terminal UI, web-first.
**Stack:** Python 3.12+ (tested on 3.14.3) + FastAPI 0.139.0 + PostgreSQL (SQLite in dev) backend; TypeScript + Vite 8.1.3 + xterm.js 6.0.0 frontend; crypto from `@noble/post-quantum` 0.6.1, `@noble/ciphers` 2.2.0, `@noble/hashes` 2.2.0 only; `liboqs-python` server-side for benchmarks and test-vector generation only. All dependency versions exact-pinned per §0; W1 verified on Node 24.5.0, npm 11.5.1.

## 0. Ground Rules (apply to every segment - violations are bugs)

**Crypto invariants**

- All asymmetric crypto is ML-KEM-768 (FIPS 203) or ML-DSA-65 (FIPS 204). If a diff introduces RSA, ECDH, X25519, Ed25519, or ECDSA into an application code path, it is wrong. CI enforces this with an import/grep audit (see §7.9).
- Never implement primitives by hand. Compose audited libraries only.
- All randomness: `crypto.getRandomValues` (client), `secrets` / `os.urandom` (server). Never `Math.random()` or `random`.
- Constants live in one shared file per side (`client/src/crypto/constants.ts`, mirrored in `server/app/constants.py`):
  - `PROTOCOL_VERSION = 1`
  - `KDF_INFO_KX = "PQTerm-v1-KX"`, `KDF_INFO_RK = "PQTerm-v1-RK"`, `KDF_INFO_CK = "PQTerm-v1-CK"`, `KDF_INFO_HDR = "PQTerm-v1-HDR"`
  - KDF: HKDF-SHA-512. AEAD: XChaCha20-Poly1305 (24-byte random nonce). Hash: SHA-512.
  - Argon2id: m = 65536 KiB, t = 3, p = 1 (params stored beside ciphertext for future upgrades).
- The server never sees plaintext, private keys, or symmetric keys. If a server function needs any of those to work, the design is wrong; stop and rethink.

**Code invariants**

- TypeScript `strict: true`; Python fully type-hinted, `mypy --strict` clean.
- No `eval`, `new Function`, `innerHTML`, `dangerouslySetInnerHTML`, `exec`, `pickle` on untrusted data. Anywhere.
- All server input crosses a Pydantic model; all client-bound data is rendered as text cells in xterm.js, never as markup.
- Uniform error responses: same shape, same timing class, no stack traces, no "user not found" vs "wrong signature" distinction externally.
- Every PR-sized change includes its tests. Crypto code targets 100% branch coverage.
- Dependencies: additions require justification in the commit message; lockfiles committed; versions pinned exact.

**Repo layout**

```
pqterm/
  client/            # TS + Vite + xterm.js
    src/terminal/    # UI, parser, renderer
    src/crypto/      # constants, kx, ratchet, store
    src/net/         # REST + WS clients
  server/
    app/             # FastAPI: routes, models, queue, auth
    tests/
  shared/vectors/    # JSON test vectors (generated by liboqs, consumed by TS tests)
  bench/             # benchmark harness + report generator
  docs/              # MVP doc, this file, ADRs
```

## 1. Website / Terminal UI & Commands

**Goal:** one interaction surface - an xterm.js terminal. Commands in, styled text out. No forms, no buttons, no modals.

**Build tasks**

1. Terminal shell: xterm.js instance, fit addon, input line editing (history with up/down, Ctrl+L clear), monospace throughout.
2. Command parser (`src/terminal/parser.ts`):
   - A line starting with `/` is tokenized against a **static allowlist** (a literal map of command name → arg schema). Anything else is message text for the active conversation.
   - A leading space escapes a literal `/` at message start.
   - Arg types are validated client-side (UID = Crockford Base32, 26 chars; durations = `^\d+(m|h|d|w)$|^off$`); reject with usage help, never guess.
   - No dynamic dispatch from user input; the parser returns a typed discriminated union consumed by a `switch`.
3. Renderer: output lines are typed events - `[✓]` success, `[!]` warning, `[✗]` failure, `[*]` info - each timestamped, written as plain text (xterm.js `write` with ANSI colors; no HTML path exists).
4. Security-critical events (identity key change, signature verification failure, SPK rotation failure) use a distinct high-visibility style and **block the affected conversation** until acknowledged with `/ack <alias>`.
5. Active-conversation model: `/chat` sets the target; a persistent status line shows `[chatting with: alias (verified|UNVERIFIED)] [timer: 1d] [locked in Xm]`.
6. Responsive layout so mobile browsers are usable (terminal fills viewport; software keyboard does not cover the input line).
7. Optional (Could-have): browser toast notifications for background events, permission requested only on first `/settings notify on`.

**Commands owned by this segment:** `/help [command]`, `/chat <alias|uid>`, `/add <uid> [alias]`, `/whoami`, `/ack <alias>`, `/settings notify <on|off>`.

**Definition of done:** parser has a fuzz test (random bytes + mutated valid commands never throw uncaught, never execute unlisted commands); no `innerHTML` anywhere (CI grep); all output paths go through the typed renderer.

## 2. Identity, Key Stores & PQC

**Goal:** passwordless PQC identity; every secret at rest is encrypted; nothing enumerable server-side.

**Build tasks**

1. **UID generation (server-authoritative):** 16 bytes from `secrets.token_bytes`, Crockford Base32, grouped `XXXX-XXXX-XXXX-XXXX-XXXX-XX`. Generated inside the registration transaction under a UNIQUE constraint; on collision, silently regenerate. **Never expose an existence-check endpoint.** Bundle lookups require an authenticated session and are rate-limited; exists/not-exists responses are uniform in shape and timing.
2. **Identity:** client generates ML-DSA-65 keypair at `/register`; uploads the public key; prints UID + one-time recovery codes (10 codes, shown once, never stored plaintext server-side - store salted hashes).
3. **Login:** server issues a 32-byte nonce bound to `origin` and timestamp, single-use, 60-second expiry, stored server-side until consumed. Client returns `ML-DSA.Sign(sk_IK, nonce ‖ origin ‖ timestamp)`. Verify → issue opaque 256-bit session token: kept in JS memory only (never `localStorage`/cookies), 15-minute idle expiry, rotated on every WS reconnect, revoked server-side on `/logout`.
4. **Local key store (`src/crypto/store.ts`):**
   - Random 256-bit DEK encrypts everything in IndexedDB (identity secret key, prekey secrets, ratchet states, message history, contacts).
   - DEK wrapped by Argon2id(passphrase) with params from §0. Changing the passphrase re-wraps the DEK only.
   - Auto-lock after 10 minutes idle; `/lock` immediate; best-effort zeroization of key material on lock (overwrite typed arrays).
5. **Passphrase rotation prompt:** default ON, fires on first unlock on/after each Friday; `/settings rotation off|on|day <weekday>`. Entirely local. Declining is allowed and unlogged.
6. **Prekeys:** on registration and weekly thereafter, generate ML-KEM-768 signed prekey (SPK) + 50 one-time prekeys (OPKs); sign SPK and the OPK batch root with IK; upload public halves. Server marks OPKs consumed atomically (one fetch = one OPK, transactional). Client auto-refills below 20; old SPK secret retained 7 days for late handshakes, then deleted.

**Commands owned by this segment:** `/register`, `/login`, `/logout`, `/lock`, `/rotate passphrase`, `/settings rotation <on|off|day <weekday>>`, `/keys status`, `/keys refill`, `/wipe` (double confirmation; deletes IndexedDB databases, best-effort overwrite first).

**Definition of done:** store survives reload locked and unlocks correctly; DB inspection during tests shows only ciphertext server-side; registration/login flows pass with clock skew ±2 min; nonce replay is rejected; a stolen (copied) IndexedDB directory without the passphrase yields nothing (test decrypts fail).

## 3. Handshakes & First Message

**Goal:** asynchronous PQ-KX (PQXDH analog, no classical DH) producing a shared root key and a delivered first message.

**Protocol (implement exactly; constants from §0):**

1. Alice fetches Bob's bundle `{IK_B, SPK_B + sig, OPK_B + sig}` (authenticated, rate-limited). Verify both signatures against `IK_B`; on failure abort with a `[✗]` security event - never proceed, never retry silently.
2. `(ct1, ss1) = ML-KEM.Encaps(SPK_B)`; if an OPK was issued: `(ct2, ss2) = ML-KEM.Encaps(OPK_B)`, else `ss2 = ∅` and the session is flagged `reduced-fs` in the UI until the first ratchet step completes.
3. `transcript = SHA-512(PROTOCOL_VERSION ‖ IK_A ‖ IK_B ‖ SPK_B ‖ ct1 [‖ OPK_B ‖ ct2])`.
4. `RK_0 = HKDF-SHA-512(ikm = ss1 ‖ ss2, salt = ∅, info = KDF_INFO_KX ‖ transcript)`.
5. `sig_A = ML-DSA.Sign(sk_IK_A, transcript)` (this authenticates Alice; documented deniability trade-off).
6. Envelope v1 (versioned, length-prefixed fields, no JSON for crypto payloads - use a fixed binary layout):
   `version ‖ type=KX ‖ IK_A ‖ ct1 ‖ [ct2] ‖ sig_A ‖ AEAD_encrypt(k = HKDF(RK_0, KDF_INFO_CK), nonce, plaintext, ad = transcript)`.
7. Bob (possibly later, on login): verify `sig_A`, decapsulate, derive `RK_0`, decrypt, **delete the consumed OPK secret immediately**, initialize ratchet state, reply through §4's ratchet.

**Transport:** REST `POST /v1/messages` enqueues; WS pushes to online recipients; client acks each message id; server deletes on ack (see §5). Payload cap 64 KiB; oversized → uniform 413.

**Definition of done:** e2e test - Alice registers, Bob registers, Bob goes offline, Alice sends, Bob logs in and reads; server row provably deleted after ack; tampered bundle signature aborts; tampered ciphertext fails AEAD; TS primitives validated against `shared/vectors/` JSON generated by liboqs (keygen/encaps/decaps and sign/verify round-trips).

## 4. Ratchet & Trust

**Goal:** forward secrecy per message, post-compromise security via continuous KEM re-keying, and a trust model that defeats a malicious server.

**Ratchet (simplified SPQR-inspired; full keys inline):**

1. **Symmetric chains:** sending/receiving chains; `CK_{n+1}, MK_n = HKDF(CK_n, KDF_INFO_CK)`; message key deleted after use. Skipped keys cached for out-of-order delivery, bounded at 256 per session (beyond → drop with `[!]` event).
2. **KEM step:** on first send of a new turn, or every 10th message of an unbroken turn, sender includes a fresh ML-KEM-768 public key in the header. Peer encapsulates to it in its next send; both mix: `RK_{i+1} = HKDF(RK_i ‖ ss_new, KDF_INFO_RK)`; new chain keys derive from `RK_{i+1}`. Old KEM secrets deleted once superseded.
3. **Header encryption:** headers (counters, epoch, KEM keys, ct) encrypted under `HKDF(RK_i, KDF_INFO_HDR)`; the server routes on an opaque envelope, not on ratchet metadata.
4. Persist ratchet state to the encrypted store after every step (crash consistency: write-ahead, then delete superseded keys).

**Trust:**

5. **Safety number:** `SN = SHA-512(min(IK_A,IK_B) ‖ max(IK_A,IK_B) ‖ UID_A ‖ UID_B)` → 60 decimal digits in 12 groups. `/verify <alias>` prints it (and a QR as Could-have).
6. `/verified <alias>` sets the flag locally. Any subsequent identity-key change: tear down session, block sending, show high-visibility warning, require `/verify` + `/verified` again. Unverified conversations show `UNVERIFIED` in the status line permanently.

**Definition of done:** FS test (dump full ratchet state, prove previously captured ciphertexts still undecryptable); PCS test (leak state, continue conversation, prove attacker copy loses decrypt ability within one full round-trip); out-of-order test (deliver messages 3,1,2 - all decrypt, skipped-key bound enforced); key-substitution test (server swaps IK_B - client refuses to send and warns).

## 5. Hardening & Life Cycles

**Message lifecycle**

1. **Server queue:** ciphertext blobs in per-recipient queue; delete-on-ack (same transaction as delivery confirmation); TTL 14 days via scheduled job; queue table excluded from any backup tooling; no delivered-message archive of any kind.
2. **Mutual disappearing timer:** `/timer <alias> <duration|off>` - carried in encrypted headers, applies to both sides, every change announced as an inline system line in both terminals, countdown starts on read. Default: off.
3. **Local purge:** `/purge set <duration|off>` (personal retention cap, never transmitted, may be stricter than the mutual timer), `/purge now [alias]` (immediate local deletion).
4. UI help and docs state plainly: peer deletion is cooperative; screenshots exist; browser deletion is not forensic erasure.

**Transport & platform hardening checklist**

- [ ] TLS 1.3 only; enable hybrid group `X25519MLKEM768` at the reverse proxy; HSTS `max-age=63072000; includeSubDomains; preload`.
- [ ] CSP exactly: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self' wss://<host>; base-uri 'none'; frame-ancestors 'none'; form-action 'none'` (tighten further if possible; loosen never).
- [ ] `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Permissions-Policy` denying everything unused.
- [ ] WS upgrade: check `Origin` against exact allowlist; authenticate **before** attaching to any queue; per-connection message-rate cap and 64 KiB frame cap; heartbeat + idle disconnect.
- [ ] Rate limits (token bucket, per-IP and per-UID): register 3/hour/IP; login-challenge 10/min/IP; bundle fetch 30/min/UID; message send 60/min/UID; exponential backoff on repeated auth failures.
- [ ] Uniform errors + uniform timing on auth and lookup paths (constant-time compares via `secrets.compare_digest`; padding-time on the not-found path).
- [ ] Logging: auth failure counts, rate-limit trips, and errors only; no message metadata beyond queue mechanics; no UIDs in logs where avoidable; log retention 30 days.
- [ ] Container: non-root user, read-only filesystem, no shell in prod image, secrets via environment/secret store, `DEBUG=0` asserted at startup (refuse to boot otherwise in prod mode).
- [ ] CORS: exact origin only, no wildcard, credentials disabled (token is not a cookie).
- [ ] CI gates: `npm audit --audit-level=high`, `pip-audit`, the classical-crypto grep (§7.9), parser fuzz test, and full test suite - all blocking.

**Commands owned by this segment:** `/timer <alias> <duration|off>`, `/purge set <duration|off>`, `/purge now [alias]`.

**Definition of done:** Mozilla Observatory (or equivalent header scan) grade A; rate-limit tests pass; a captured queue row disappears on ack in the same transaction; TTL job evicts correctly; timers fire on both simulated clients.

## 7. Security Gap Sweep (OWASP-informed; items the original guidelines did not cover)

Work through this as a checklist near the end of each milestone. References: OWASP Top 10 (2021), OWASP ASVS 4.x, OWASP WebSocket and Password Storage cheat sheets.

1. **A01 Broken Access Control:** every queue and bundle endpoint authorizes against the session's UID (a user can pull only their own queue, ack only their own message ids, upload only their own prekeys). Write explicit IDOR tests: user A attempting each of B's resources gets uniform 404s.
2. **A02 Cryptographic Failures:** no secrets in URLs or query strings; no key material in logs, error messages, or analytics (there are no analytics); AEAD nonces random per message and never reused with the same key (test: nonce uniqueness over 10⁶ encryptions); Argon2id params asserted at startup.
3. **A03 Injection:** SQL only through the ORM/parameterized queries (CI grep for f-string SQL); the terminal parser allowlist (§1); server treats message payloads as opaque bytes with a size cap - it never parses them.
4. **A04 Insecure Design - abuse cases to defend and test:**
   - Message-flood spam → per-UID send limits + per-conversation client-side mute (`/add` implies accept; unknown-sender first contact is queued behind a `[!] new contact request` line, not auto-opened).
   - **OPK depletion DoS** (attacker drains a victim's one-time prekeys via repeated bundle fetches) → per-requester fetch caps, OPK issue rate-limited per requesting UID, handshake degrades to SPK-only with `reduced-fs` flag instead of failing.
   - Registration flooding → IP rate limit + optional proof-of-work challenge (Could-have).
   - Ack forgery → acks accepted only from the authenticated recipient's session.
5. **A05 Security Misconfiguration:** headers per §5; FastAPI docs/openapi endpoints disabled in prod; default-deny CORS; server banner/version headers stripped; SQLite dev artifacts never deployed.
6. **A06 Vulnerable & Outdated Components:** exact-pinned lockfiles; `pip-audit` + `npm audit` blocking in CI; Dependabot weekly; the dependency set stays small enough to review by hand (target: client crypto deps are exactly the three `@noble` packages).
7. **A07 Identification & Authentication Failures:** login nonces single-use with 60 s expiry and origin binding (replay test required); session idle timeout 15 min; token rotation on WS reconnect; recovery codes hashed (Argon2id) server-side, burned on use; no password → no credential stuffing surface, document this in the report.
8. **A08 Software & Data Integrity Failures:** zero CDN assets (everything bundled and served same-origin; if ever violated, SRI required); CI builds are reproducible-ish (locked toolchain versions); no auto-update mechanism in MVP.
9. **A09 Security Logging & Monitoring Failures:** counters for auth failures, rate-limit trips, signature-verification failures (the last is a potential attack signal - alert on spikes); logs are privacy-minimal per §5 but sufficient to notice an active attack; a `SECURITY.md` with a disclosure contact.
10. **A10 SSRF:** the server makes **no** outbound HTTP requests by design; assert with a test that no code path constructs an outbound URL from user input (grep + no HTTP client dependency server-side beyond test tooling).
11. **WebSocket specifics (OWASP WS cheat sheet):** origin check on upgrade; auth before subscribe; per-frame size cap; backpressure (drop + `[!]` rather than unbounded buffering); heartbeat with idle kill.
12. **Client-side platform limits (document, don't hand-wave):** XSS = key theft despite CSP (keys must live in JS memory; WebCrypto has no ML-KEM/ML-DSA) - CSP is the mitigation, not a cure; JS timing side channels are plausible; IndexedDB deletion is not forensic erasure. These go in the report's limitations section verbatim.
13. **Timing discipline:** `secrets.compare_digest` for token and recovery-code comparison; uniform-shape responses on the user-lookup path (anti-enumeration, pairs with §2.1).
14. **Availability honesty:** rate limiting is the only DoS defense in MVP; state this as a non-goal rather than implying resilience.
15. **Supply-chain hygiene for the crypto libs:** pin `@noble/post-quantum` to the audited version; record the version + audit reference in an ADR; never float crypto dependency versions.

## 8. Build Order (maps to MVP doc §11)

1. **W1:** ✓ done. §1 shell + parser, server skeleton, §2.1 UID/registration transaction, CI with all §5 gates in place.
2. **W2:** ✓ done. Identity and local key store: `/login` challenge–response over ML-DSA-65 (server nonce + client signature, verified server-side via pyca `cryptography` 49.0.0), session tokens (256-bit, SHA-512 at rest, 15m idle; WS-reconnect rotation lands with WS in W3), Argon2id-wrapped IndexedDB store (DEK + passphrase), SPK (7-day rotation + 7-day retention for late handshakes) + OPK bundle (50 one-time keys, low-watermark refill < 20, batch-signed via SHA-512 leaf/root, leaf list retained server-side so single OPKs stay verifiable), recovery codes (printed once, Argon2id hashes only server-side; redemption endpoint deferred to W5), `/rotate passphrase`, `/lock`, `/logout`, `/keys status`, `/keys refill`, `/settings rotation <on|off|day <weekday>>`, `/wipe` (double confirm), 10-min auto-lock. Login binds nonce to origin+timestamp; challenge echoes the bound origin so the client signs the server-seen bytes.
3. **W3:** §3 complete (PQ-KX, first message, queue with delete-on-ack + TTL).
4. **W4:** §4 complete (ratchet, safety numbers, key-change teardown).
5. **W5:** §5 complete + §7 sweep executed as a dedicated hardening pass.
6. **W6:** `/bench` + `bench/` harness (suites B1-B5 per MVP doc §8), report tables, demo script, buffer.

**Scope-cut order if behind:** B4/B5 benchmarks → toasts/QR/themes → `/wipe` → local purge (keep mutual timer) → header encryption. Never cut: ratchet FS/PCS, safety numbers, delete-on-ack queue, the §7 sweep items 1-3 and 7.
